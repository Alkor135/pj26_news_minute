# Изменяемый коэффициент динамического порога

15.10.2026. База — годовая история, 106 запросов сентября 2026, 2120 оценок
по двум моделям, MIX/RTS и пяти горизонтам. Введён параметр k>0:

`T_effective = k × T_base`, где `T_base = sigma_news × Q75(abs(R_background)/sigma_background)`.

База остаётся динамической и использует только прошлое каждого события. Пять
соседей не пересчитываются: меняется медиана abs(R_neighbor)/(k*T_neighbor).
Она должна быть >=1. Пять ненулевых знаков должны совпадать, косинусы/категории/
разные даты/скользящий год/полнота окон сохранены. Исход текущей новости не
используется для решения. Неполный текущий исход не удаляет прогноз.

Первые числа — оценки модель/инструмент/горизонт, а не независимые сделки.
У трёх из 35 отборов при k=0,5 текущий исход неполон; они сохранены, но не входят
в подсчёт совпадений. Снижение k меняет как состав отборов, так и требуемую силу
фактического движения. Поэтому последняя колонка сохраняет единый критерий k=1.
Нельзя считать рост предпоследней колонки одним лишь улучшением прогнозирования.
Издержки здесь не учитываются.

Лучший k автоматически не выбирался. k=0,50 открыт в finplot как демонстрация
управления. База на диске оставлена с k=1. Значения сравнивались на сентябре,
поэтому этот месяц теперь используется для исследования параметра; выбранное
значение следует отдельно проверить на последующем периоде. Статистика не
подтверждает доходность стратегии.

## Управление и файлы

В finplot поле «Порог ×» мгновенно меняет список отборов, пункты порога и |R|/T
для запроса и соседей. Два десятичных знака, минимум 0,01. Выбранная новость
сохраняется, если проходит новый фильтр. Вернуться к прежнему режиму можно k=1.
Переключения в окне не записываются в БД; метрики исторической устойчивости
не изменяются этим коэффициентом.

```powershell
.\.venv\Scripts\python.exe tune_threshold.py --multipliers 0.1 0.25 0.5 0.75 1 1.25 1.5
.\.venv\Scripts\python.exe view_news_finplot.py --database data\russian_market\2026-09_year1\reactions\reactions.sqlite3 --analogs data\russian_market\2026-09_year1\analogs\analogs.sqlite3 --instrument RTS --horizon 15 --threshold-multiplier 0.5
```

Экспорт data/russian_market/2026-09_year1/analogs/threshold_tuning:

- summary.csv — все значения и разрезы модель/инструмент/горизонт;
- selected.csv — все отборы каждого k, направления, известность исхода и ID соседей;
- summary.json — полный список k, исходные настройки и SHA256 базы;
- finplot_threshold.png — снимок открытого просмотра.

`--database` и `--output` задают другую БД/папку сравнения. Для фиксации параметра
в полной сборке используется --threshold-multiplier у build_analogs.py и
russian_market.py. По умолчанию k=1. Для GUI/сравнения тики и эмбеддинги не нужны.
В thresholds SQLite остаются базовые калибровки, scores хранит базовые и
эффективные значения. Старые базы без этих полей читаются как k=1.

## Проверки

42 теста прошли, включая масштабирование, неизменность соседей, запрет NaN/Inf/
неположительного k, обратимость, независимость от текущего исхода, экспорт всех
испытаний и живое переключение Qt. Синтетическая SQLite не изменяется при экспорте.
Годовая база пересчитана при k=1: все 2120 решения и выбранные метрики совпали
с прежними точно, SHA256 канонического набора полей до/после одинаковый:
e822a4e1e92aa696b1949360007fb92b9e691cd93a9097b73634ccc7e0ad4081.
Независимое ревью существенных дефектов не обнаружило.
