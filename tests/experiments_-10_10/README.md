# Проверки обучения шкале −10…+10

С 18.10.2026 обучение по умолчанию использует три класса (`--task extremes`),
а `--task score` сохраняет балльный режим. `test_extremes.py` проверяет границы
±8, строгий JSON класса, воспроизводимость балансировки, сохранение всех
исходных строк, отказ при отсутствии класса, метрики ложных сигналов и пропусков,
реальный CLI с неизменённой валидацией и отдельное имя при импорте.
Временные файлы находятся в `tests/tmp_extremes_*` и удаляются.

`test_orchestrator.py` проверяет последовательность 3–8 для RTX 4070,
передачу одного каталога и задачи extremes всем этапам, безопасный `--dry-run`,
остановку после первой ошибки процесса и отказ от перезаписи обучения до
разметки. Внешние процессы заменены; CUDA, новости и Ollama не запускаются.
Временные файлы создаются в `tests/tmp_orchestrator_*` и удаляются.
Для `--final-test` проверяются отдельные пути/имя, включение сентября в
разметку, границы годового обучения и сентябрьского теста, сохранение явно
заданных путей. `test_training.py` проверяет перенос августа в обучение и
исключение сентября из него; `test_check_model.py` восстанавливает сохранённый
сентябрьский тест только при явной роли test. Временные проверки данных
не запускают GPU и не оценивают настоящую модель за сентябрь.
Для `--delete-labels` проверяются удаление JSONL и сводки перед запуском
разметки, сохранение соседних файлов и всех файлов при `--dry-run`, допустимость
отсутствующей разметки и отказ от удаления без последующего этапа 3.
Команда отдельного запуска:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/experiments_-10_10 -p test_orchestrator.py -v
```

`test_html_report.py` проверяет числа в HTML-отчёте, наличие таблицы сравнения,
фильтров и пояснений, экранирование текста новости, создание HTML из одного
JSON без других этапов и неизменность исходных файлов. При несовпадении
SHA-256 разметки заголовки не подмешиваются. Временные файлы создаются только
в `tests/tmp_html_*` и удаляются.
При наличии Node.js встроенные JavaScript-фильтры исполняются на минимальном
тестовом DOM без браузера и сети; без Node.js пропускается только эта проверка.
Также проверяется сохранение котировок после SHA-256, знак результата условной
короткой позиции, направление при балле 0, недоступность результата без цен,
отказ при противоречии points и разности цен, вывод о торговле и отдельная
таблица ложных сигналов с пунктами.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/experiments_-10_10 -p test_html_report.py -v
```

`test_rasmetka.py` проверяет балльную формулу, пропуски, согласованность
`stable`, отказ от несовместимой версии реакции и сквозной путь от RSS и ZIP
котировок до JSONL. Временные файлы размещаются только внутри `tests`.

`test_training.py` загружает общий модуль из
`experiments_-10_10/source/training_common.py` и проверяет отсутствие подмены пропусков нулём, валидацию
баллов и обязательных полей (включая null и неверную структуру JSON), целостность
новостей, временные границы и перепечатки, отсутствие будущих
метрик во входе модели, маску ответа и оба запуска в режиме `--dry-run`.
Проверяется запуск без обязательного `--data`: оба профиля по умолчанию выбирают
`data/experiments_-10_10/scores.jsonl`, явный аргумент позволяет сменить файл.
Временные данные создаются в `tests/tmp_training_*` и удаляются после тестов.
`__init__.py` включает каталог в общую проверку проекта.
`test_ollama_transfer.py` проверяет совместимость базы и адаптера, привязку
его SHA-256 к ревизии и отказ от незавершённого обучения, целостность GGUF,
создание полного экспорта только
после конвертации, защиту занятого имени Ollama и формат пробного балла.
Тяжёлую загрузку весов и внешнюю конвертацию тест заменяет временными файлами
в `tests/tmp_ollama_*`; реальный экспорт и сервер Ollama в тесте не запускаются.
Проверяется также экспорт без `--run`: выбор единственного завершённого профиля,
отказ при двух профилях или отсутствии завершённого обучения, стандартный путь llama.cpp.
Для импорта без `--export` проверяется выбор каждого из профилей, проверка GGUF
без Ollama, отказ при двух экспортах и при отсутствии экспортов.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/experiments_-10_10 -v
```

Это проверки подготовки и интерфейса; успешное выполнение не подтверждает
совместимость CUDA или качество обученной модели.

Отдельная ручная проверка CUDA и библиотек обучения:

```powershell
.\.venv\Scripts\python.exe tests/experiments_-10_10/check_training_environment.py
```

`check_training_environment.py` создаёт синтетическую Qwen3 со случайными весами
в `tests/tmp_qlora_*`, загружает её в NF4, добавляет LoRA и выполняет один шаг
AdamW через Trainer с проверкой обновления весов и сохранения адаптера. Временная папка
удаляется; модели из сети и файловые логи не создаются. Нужна NVIDIA GPU CUDA.

Проверка подготовленного llama.cpp:

```powershell
.\.venv\Scripts\python.exe tests/experiments_-10_10/check_llama_cpp.py
```

`check_llama_cpp.py` создаёт маленькую Qwen3 со случайными весами и токенизатором
из `data/experiments_-10_10/RTX4070/adapter`, выполняет настоящую конвертацию F16
GGUF и квантование Q4_K_M. Проверяет наличие тензоров Q4_K и уменьшение размера.
Параметры `--tokenizer-dir` и `--llama-cpp-dir` меняют пути к токенизатору и
инструментам. Нужен уже сохранённый токенизатор Qwen3; новые веса не скачиваются.
GPU не требуется. Временная папка `tests/tmp_llama_cpp_*` удаляется после проверки.

## Проверка импортированной модели

`check_model.py` оценивает модель Ollama на сохранённых валидационных примерах
обучения. Проверяет SHA-256 разметки, восстанавливает временное разделение,
сверяет примеры. Целевые баллы в запросах не используются. Сентябрь 2026
допускается только при явной роли `evaluation_role=test` в параметрах обучения;
по умолчанию остаётся августовская валидация.
Без параметров выбирает единственный профиль с `export/import_report.json`
и проверяет первые 32 примера сохранённой подвыборки (обычно из 256).

```powershell
.\.venv\Scripts\python.exe tests/experiments_-10_10/check_model.py
.\.venv\Scripts\python.exe tests/experiments_-10_10/check_model.py --limit 0
.\.venv\Scripts\python.exe tests/experiments_-10_10/check_model.py --run data/experiments_-10_10/RTX3090Ti
.\.venv\Scripts\python.exe tests/experiments_-10_10/check_model.py --prepare-only
```

Параметры: `--run` — каталог обучения, `--data` — исходная разметка
(по умолчанию `data/experiments_-10_10/scores.jsonl`), `--name`, `--host` —
модель и сервер (из отчёта импорта), `--limit` — число примеров (32; 0 — вся
сохранённая подвыборка), `--prepare-only` — проверить данные без Ollama и записи.
При двух импортированных профилях нужен явный `--run`.

Результат перезаписывается в `RUN/check_model_report.json`. Метрики: MAE
(меньше — лучше), ошибки JSON, точное совпадение, совпадение знака при
ненулевой фактической метке, разбивка по инструменту/горизонту. MAE модели
сравнивается с нулём на одинаковых корректно оценённых строках. Отдельно
приводятся результаты исходного адаптера на выбранных примерах.
Задержка включает API, генерацию и возможную загрузку модели. Проверяется
текущая модель под указанным именем; идентичность её весов экспорту не доказана.
При потере соединения проверка останавливается без публикации частичного отчёта.
Код 0 означает корректность всех ответов, а не преимущество над нулём.
Это проверка баллов, не доходности стратегии.

Для `extremes` тот же `check_model.py` использует контракт `class` из манифеста
и вместо MAE считает precision/recall/F1, количество сигналов и матрицу ошибок.
Поддерживаются каталоги `_extremes`. Если есть старая и новая модель, нужен
явный `--run`. Для редких классов проверять всю сохранённую валидацию:

```powershell
.\.venv\Scripts\python.exe tests/experiments_-10_10/check_model.py --run data/experiments_-10_10/RTX4070_extremes --limit 0
```

У нового обучения по умолчанию сохранены все 613 валидационных примеров.
Поля `classes.negative` и `classes.positive` содержат точность, полноту и
число ложных сигналов. Неверный JSON снижает полноту; отсутствие сигналов
даёт precision=null. Общая accuracy на большинстве `none` не подтверждает
способность распознавать экстремумы.

`test_check_model.py` проверяет метрики с пропусками, отсутствие балла в запросе
и строгий формат ответа без Ollama:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests/experiments_-10_10 -p test_check_model.py -v
```
