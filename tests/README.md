# Проверки пилота эмбеддингов

`experiments_-10_10/test_rasmetka.py` проверяет формулу баллов −10…+10, отличие нулевой и
отсутствующей метки, крайние значения по `stable`, согласованную версию
ценовых метрик и вывод JSONL для скриптов дообучения. Сквозная проверка
создаёт искусственные RSS SQLite и ZIP котировок внутри `tests`, затем
проверяет путь от исходных файлов до десяти размеченных реакций.

Каталог `experiments_-10_10` содержит проверки подготовки данных и двух запусков
дообучения для RTX 4070 и RTX 3090 Ti. Описание и отдельная команда запуска —
в [README эксперимента](experiments_-10_10/README.md).

`test_embedding_pilot.py` проверяет дедупликацию с сохранением первой загрузки,
отбор по loaded_at, нормализацию и валидацию векторов, раздельное хранение моделей
и поиск аналогов без будущих записей, а также экранирование HTML и поля CSV
для ручной оценки и сброс векторов при изменении входного текста.
Реальный Ollama для модульных тестов не нужен.
Временные базы создаются внутри `tests` и удаляются после проверки.

`test_price_reactions.py` проверяет секундные границы входа/выхода, OHLCV,
пропуски и неполные окна, экстремумы, отсутствие будущих свечей в sigma_pre и
отказ от устаревшей предыстории после перерыва торгов.
`test_finplot_compat.py` в дочернем процессе проверяет реальный импорт finplot
при русской локали и восстановление функции locale.
`test_finplot_smoke.py` создаёт Qt без рабочего стола (offscreen), строит свечи
и маркеры, проверяет точное положение отметки новости, сохранение повторной
загрузки заголовка в контексте и переключение инструмента.
Последние два теста требуют установленных зависимостей requirements.txt.

`test_dynamic_analogs.py` проверяет динамическое масштабирование порога,
исключение текущего/будущих дней, нехватку и нулевой фон, пять разных дат,
отсутствие замены несогласного соседа и медиану силы без фильтра устойчивости.
`test_analog_pipeline.py` проверяет версии из manifest, точное соответствие
текста эмбеддингу, отказ при пропавшей модели и независимость прогноза от
подмены текущего исхода на положительный, отрицательный или отсутствующий.
Дополнительный тест finplot сохраняет отобранный прогноз при отсутствии будущих
котировок (`no_entry`) и `stable=False`.
`test_analog_output.py` проверяет всю созданную БД аналогов: целостность SQLite,
собственную прошлую историю каждого порога, уникальность дат, доступность исходов
и воспроизводимость решений. При отсутствии результата тест пропускается.

`test_market_relevance.py` проверяет релевантные события и ложные совпадения
(Газета, иностранные акции/газ/ставки, переговоры о членстве в ЕС, обзоры FTSE),
совместимость типа/объекта/стадии, восстановление против нарушения поставок,
намерение против решения о дивидендах, ранжирование после тематического фильтра
и сохранение ручной разметки при повторном запуске.
`test_dynamic_analogs.py` дополнительно проверяет пять непоследовательных дат с
интервалами в несколько месяцев. `test_analog_output.py` проверяет старую базу и
все готовые месячные базы data/russian_market, включая тематическую совместимость.
Qt-тест проверяет категории, объяснения и переключение фильтра.

Запуск из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`test_year_history.py` проверяет скользящий календарный год и его точную границу,
29 февраля, непоследовательные даты, отделение месяца оценки от истории,
сохранение одинаковых заголовков разных дней и переиспользование векторов только
по точному тексту с раздельными версиями модели. `test_analog_output.py` проверяет
также нижнюю годовую границу каждого соседа, период запросов и query_count.

`test_threshold_tuning.py` проверяет масштабирование T=k*T_base у запроса и
аналогов, неизменность их состава, отсутствие накопления k при переключениях,
отдельную оценку общего базового порога, сохранение условий знаков/истории,
независимость отбора от текущего исхода и отказ для k<=0/NaN/Inf. Интеграция
синтетической SQLite проверяет все испытанные значения, неизменность исходной
БД и полную схему пустого CSV. Qt-тест проверяет живые переходы 1→0.5→0.4→1→0.5,
обновление порогов соседей и метрик при сохранении выбранной новости.
