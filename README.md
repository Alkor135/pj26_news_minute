# pj26_news_minute

Исследование направленных движений фьючерсов MIX и RTS после получения новостей.
Первый предлагаемый результат — минутный свечной график finplot с отмеченными
новостями и исторической оценкой последующего движения.

## Текущее состояние

- Выполнен первичный аудит структуры новостей и образцов тиков.
- Подготовлен [обзор исследований и предложение решения](docs/research.md).
- Создано виртуальное окружение `.venv`: Python 3.14.8, pip 26.2.1.
- Реализован пилот сравнения эмбеддингов через локальный Ollama.
- Выполнен реальный прогон: 2000 новостей, 4000 векторов, 600 строк аналогов;
  [наблюдения и замеры](docs/embedding-pilot-results.md).
- Рассчитаны 20 000 реакций MIX/RTS по 2000 новостей; 15 401 полное окно,
  213 сочетаний «новость–инструмент–горизонт» с исторической меткой устойчивости.
- Реализован просмотр минутных свечей, новостей и метрик в finplot.
- Исходные базы и архивы не изменяются.

## Пилот эмбеддингов

`embedding_pilot.py` читает новости по `loaded_at` за выбранный месяц, объединяет
одинаковые заголовки после NFKC/нормализации пробелов без учёта регистра, сохраняет
первую загрузку внутри месяца и число повторов. Случайная выборка воспроизводима
при неизменных БД и seed. Векторы считаются по заголовкам без инструкционных
префиксов: симметричное сравнение новость–новость. Это базовый вариант, а не
оптимизация рекомендованных для поиска запрос–документ инструкций Qwen.

Нужен работающий Ollama с моделями `qwen3-embedding:0.6b` и `bge-m3:latest`.
Скрипт не скачивает модели и не устанавливает сторонние Python-зависимости.

```powershell
.\.venv\Scripts\python.exe embedding_pilot.py
.\.venv\Scripts\python.exe embedding_pilot.py --month 2026-09 --limit 2000 --batch-size 32
.\.venv\Scripts\python.exe embedding_pilot.py --models bge-m3:latest --limit 1000
.\.venv\Scripts\python.exe embedding_pilot.py --help
```

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--news-dir` | `C:\Users\Alkor\gd\db_rss` | Папка исходных помесячных SQLite |
| `--month` | `2026-09` | Месяц доступности по loaded_at |
| `--limit` | `2000` | Максимальное число уникальных заголовков |

| `--models` | обе модели выше | Один или несколько точных тегов Ollama |

`source/embedding_report.py` формирует HTML и CSV по рассчитанным результатам; отдельно
не запускается. Его функция `write_report` получает папку, новости, аналоги и
метаданные. Результаты:

- `pilot.sqlite3`: таблицы `news`, `samples`, `models`, `embeddings`, `benchmarks`.
  Векторы — нормированные float32 little-endian BLOB, с размерностью, digest и
  версией подготовки. Кэш сохраняется после каждого пакета; перезапуск использует
  готовые векторы. Изменение текста заголовка сбрасывает его прежние векторы;
  изменение только времени/источника не требует пересчёта. Время прогрева и новых
  HTTP-вычислений измеряется отдельно.
- `report.html`: сравнение моделей рядом, весь месяц и отдельно только прошлое.
- `review.csv`: аналоги с полями ручной оценки `relevance_0_1_2`,
  `same_event_yes_no`, `action_match_yes_no`, `notes`.
- `news.csv`: выбранные заголовки и время первой загрузки внутри месяца.
- `summary.json`: настройки, отпечаток выборки, статистика источника и замеры.

Отчёты имеют постоянные имена и перезаписываются. Перед ручной разметкой сохраните
копию `review.csv`. Данные и кэш исключены из Git. Файловых логов нет.
Для новых моделей результаты хранятся отдельно, даже при одинаковой размерности.
При возобновлении замер относится только к новым текстам; прежний замер сохраняется
для той же выборки, если всё взято из кэша.

Режим `all` допускает будущее и служит исключительно оценке текстового сходства.
Режим `past` исключает сам запрос и заголовки с loaded_at позже запроса минус
120 минут. Смысловые перепечатки автоматически не исключаются. Ни один режим
пока не использует котировки и не оценивает торговое преимущество.

  MFE/MAE, откаты, ER и Z для каждого горизонта.
- `reactions_long.csv`: отдельная строка на каждый горизонт, время/цена входа
  и выхода, все метрики и флаги качества.
- `coverage.csv`: состояние архивов и покрытие каждого обработанного дня.
- `summary.json`: параметры, сводка качества и число исторических кандидатов.

### Определение метрик

Возможный вход — первая строка тиков **после всей секунды** `loaded_at+latency`.
Сделки внутри той же секунды исключаются из-за искусственных дробей. Горизонт
начинается от секунды фактического входа; цена конца — последняя сделка строго
до секунды `entry_at+H`. Это наблюдаемые цены сделок, не гарантия исполнения заявки.

Минутные свечи соответствуют `[HH:MM:00, HH:MM+1:00)`; отсутствие сделок не
заполняется искусственными свечами. Окна с пробелом более 120 секунд, слишком
поздним входом, устаревшим выходом, отсутствующим архивом или переходом даты
сохраняются с неполным статусом и пустым движением. Причину показывает status.

- `points`: цена конца минус цена входа; `return_pct`: изменение в процентах.
- `direction`: up/down/flat. Нейтральная зона: до 50 пунктов включительно MIX,
  до 20 RTS. Это исследовательские пороги, не комиссии и не спред.
- MFE/MAE: максимальное благоприятное/неблагоприятное отклонение относительно
  входа по фактическому знаку конечного изменения; при нулевом изменении пусты.
- Максимальный откат: наибольшее снижение от достигнутого экстремума в направлении
  конечного изменения. MFE/MAE/откат рассчитаны по тикам.
- ER: модуль конечного изменения / сумма модулей изменений по пути от входа
  через завершённые минутные закрытия к цене конца. При постоянной цене пусто.
- Доля направленных минут: доля завершённых после входа свечей, закрывшихся
  по итоговой стороне от цены входа.
- `sigma_pre`: стандартное отклонение 60 минутных доходностей до loaded_at;
  требуются 61 последовательная завершённая свеча без пропусков, причём последняя
  должна быть минутой непосредственно перед минутой новости.
- `z_score`: `abs(points/entry_price)/(sigma_pre*sqrt(H))`.
- `stable`: direction не flat, Z>=2, ER>=0.45, доля>=0.7,
  MAE и максимальный откат <= половины модуля конечного изменения.

Критерии стартовые и задают историческую разметку, а не статистически доказанный
сигнал. Связанные новости и пересекающиеся горизонты не независимы. Статус ok
означает прохождение проверок полноты; все строки сохраняют флаг
`continuous_contract_unverified`, поскольку код отдельного контракта отсутствует.
Комиссии, спред и проскальзывание на этом этапе не вычитаются.

на момент входа. Временная шкала явно МСК; точность ns задана для совместимости
примитивов finplot с pandas 3. Кнопка «Сохранить PNG» перезаписывает `finplot.png`.

Дополнительно: `--database` задаёт готовую SQLite, `--news-dir` — RSS для контекста,
`--instrument MIX|RTS`, `--horizon 5|15|30|60|120`, `--all-events`, `--search`,
`--screenshot`. Все параметры: `--help`.

В finplot 1.9.7 найдено жёсткое завершение процесса при русской/белорусской локали.
Модуль `source/finplot_compat.py` только на время импорта подставляет нейтральный
ответ функции locale.getdefaultlocale и восстанавливает её в finally. Настройки
Windows и файлы установленной библиотеки не меняются; интерфейс остаётся русским.

## Пять прошлых аналогов и динамический порог

```powershell
.\.venv\Scripts\python.exe build_analogs.py
.\.venv\Scripts\python.exe build_analogs.py --quantile 0.75 --min-similarity 0.5
.\.venv\Scripts\python.exe view_news_finplot.py --selection-mode analogs
.\.venv\Scripts\python.exe view_news_finplot.py --selection-mode assessments
.\.venv\Scripts\python.exe view_news_finplot.py --selection-mode stable
```

`build_analogs.py` — четвёртая исполняемая команда; реализация в source.
Остальные параметры: `--reaction-db`, `--pilot-dir`, `--output`, `--mix-dir`,
`--rts-dir`, `--models` (по умолчанию обе модели), `--lookback-days 20`,
`--time-band-minutes 60`, `--min-samples 30`, `--min-days 5`,
`--volatility-fraction 0.5`, `--background-step 15`. Входные данные не изменяются.
Векторы выбираются по digest текущего manifest пилота, с проверкой подготовки,
состава и точного текста. БД реакций и БД пилота должны соответствовать.

Для каждого инструмента и горизонта допустимы прошлые новости с полной реакцией
и рассчитанным собственным порогом. Берётся наиболее похожая новость каждой
прошлой даты, затем пять ближайших дат; текущий день целиком исключён, конец
каждого окна должен быть уже известен. Ранжирование не использует знак, силу,
ER или устойчивость. Несогласный/слабый сосед не заменяется шестым.
Нужны пять одинаковых ненулевых знаков и медиана `abs(R)/T >= 1`.
Минимальный косинус 0.5 — отдельное исследовательское ограничение, пока не
откалиброванное; он не означает вероятность. Параметры не выбирались по прибыли.

Фон — интервалы по сетке 15 минут с теми же тиковыми правилами входа/выхода.
Из предыдущих 20 доступных дней берутся часы ±60 минут, будни и выходные
разделяются. Из них выбирается ближайшая по `log(sigma)` половина (не меньше
30 интервалов), минимум пять дат. `T = sigma_новости * Q75(abs(R_фона)/sigma_фона)`.
Это порог доходности; пункты для отображения вычисляются по последнему
завершённому минутному close до loaded_at. Порог каждого аналога использует
историю до него самого. При нехватке данных/нулевом пороге отказ без фиксированной
подстановки. Фон содержит и обычные, и новостные периоды рынка.

`data/analog_analysis/analogs.sqlite3`: news, thresholds и scores всех оценок,
включая отказы; JSON payload содержит пять соседей и происхождение порога.
`scores.csv` — плоские оценки, `summary.json` — параметры/версии/сводка.
`background.sqlite3` — кэш интервалов, проверяемый по SHA256 архивов и настройкам.
Готовая БД аналогов заменяется после успешного расчёта. Изменение БД реакций
требует повторного расчёта: GUI проверяет SHA256. Путь GUI: `--analogs`.

Вкладка «Пять прошлых аналогов» показывает дату, текст, косинус, движение,
собственный динамический порог и отношение |R|/T. Двойной щелчок открывает график
аналога, кнопка возвращает выбранный запрос. Фактическое движение запроса не
влияет на отбор, даже если его котировки отсутствуют; оно показано только для
оценки прогноза. Старые fixed neutral_points и stable к новому отбору не применяются.
Метрики риска сохраняются для исследования.

Первый результат и ограничения: [docs/dynamic-analogs-results.md](docs/dynamic-analogs-results.md).

Пятая исполняемая команда `russian_market.py` обрабатывает всю ленту месяца ДО
эмбеддингов. Реализация и правила в source. Только include получает эмбеддинги и
ценовые реакции. uncertain сохраняется для проверки без догадок о полном тексте.
Категории: геополитика/санкции, ставка/инфляция России, нефть, валютное регулирование,
корпоративные события восьми российских компаний. Словарь компаний не объявляется
историческим составом индекса; веса не используются. Общий газовый рынок и
зарубежная макростатистика пока вне основного набора. LLM не подключён.

Аналоги должны иметь общий объект, тип события и стадию: ожидание, запланированное
событие, сообщение о факте или комментарий. Неясная стадия даёт uncertain.
Пять разных дат не обязаны идти подряд, все раньше дня запроса; ограничение
20 прошлых дней касается только ценового фона. Ценовые условия не ослаблялись.

Параметры: `--month`, `--history-years`, `--stage classify|all`, `--news-dir`, `--output`, `--models`,
`--ollama-url`, `--batch-size`. Выход data/russian_market/2026-09:
classification.csv (все решения/причины), classification_summary.json (сводка),
review_blind.csv (до 60 примеров каждого решения без цен, human_* для разметки),
pilot/reactions/analogs (кэши, SQLite, CSV, JSON). Ручные поля неизменных заголовков
сохраняются при повторном запуске. GUI показывает категорию и объяснение фильтра.

Отчёт: [docs/russian-market-results.md](docs/russian-market-results.md).

## Поиск аналогов за год

```powershell
.\.venv\Scripts\python.exe russian_market.py --month 2026-09 --history-years 1
.\.venv\Scripts\python.exe view_news_finplot.py --database data\russian_market\2026-09_year1\reactions\reactions.sqlite3 --analogs data\russian_market\2026-09_year1\analogs\analogs.sqlite3 --selection-mode assessments
```

`--history-years 1` теперь значение по умолчанию. Сентябрь 2026 остаётся месяцем
проверки, история кандидатов загружается с сентября 2025. Для каждой новости
действует собственная нижняя граница loaded_at минус календарный год, верхняя —
начало её даты. Даты любых пяти аналогов разные и не обязаны идти подряд.
Исторические новости не входят в статистику запросов сентября. 20 дней фона
не меняют годовое окно поиска текстов. Результаты отдельно в 2026-09_year1.
Для прежней месячной пробы укажите `--history-years 0`.

В годовом наборе одинаковые тексты разных дат сохранены как отдельные события;
повторные загрузки внутри дня объединены по первому loaded_at. Это изменение
дедупликации отдельно от расширения диапазона, поэтому сравнение со старой
месячной пробой не является чистым сравнением одного параметра. Векторы точного
текста переиспользуются; фильтр российского рынка и ценовые условия не изменены.

Реальная RSS-история начинается 26.09.2025: в начале сентября 2026 полного года
нет. Покрытие по месяцам и фактические границы записаны в classification_summary.json.
Поиск использует доступную часть запрошенного годового окна, без будущих данных.

Результат годовой пробы: [docs/year-analogs-results.md](docs/year-analogs-results.md).
На тех же 106 запросах получено 7 отборов по 5 новостям; только одна оценка
достигла динамического порога в прогнозную сторону. Это исследовательский
результат с пересекающимися оценками, не подтверждение доходности стратегии.

## Изменение строгости динамического порога

Порог теперь T = k × T_base, где T_base по-прежнему вычисляется из прошлой
волатильности и распределения движений. k=1 сохраняет прежний вариант, k<1
смягчает отбор, k>1 ужесточает. Один k применяется к каждому аналогу и запросу.
Сами пять соседей, годовая история, разные даты, совпадение знаков и минимум
косинуса остаются прежними. Результат текущей новости не влияет на её отбор.

```powershell
.\.venv\Scripts\python.exe tune_threshold.py --multipliers 0.1 0.25 0.5 0.75 1 1.25 1.5
.\.venv\Scripts\python.exe view_news_finplot.py --database data\russian_market\2026-09_year1\reactions\reactions.sqlite3 --analogs data\russian_market\2026-09_year1\analogs\analogs.sqlite3 --threshold-multiplier 0.5
```

В finplot поле «Порог ×» меняет k без тиков/Ollama/перестроения БД. Порог в пунктах,
отношения |R|/T и отборы обновляются, выбранная новость по возможности сохраняется.
GUI поддерживает два десятичных знака и k>=0.01; CLI расчёта/сравнения допускает
любое конечное положительное число. Начальный k из БД, по умолчанию 1, переопределяется
--threshold-multiplier. В режиме исторической устойчивости поле отключено.

Новая шестая команда tune_threshold.py сохраняет все испытания без автоматического
выбора «лучшего»: --database (по умолчанию годовая БД), --output (папка
threshold_tuning рядом с БД), --multipliers. Выход: summary.csv, selected.csv,
summary.json с параметрами/SHA256. Число отборов считается отдельно от числа
известных исходов. effective_target_hits — достижение k*T_base в прогнозную сторону,
base_target_hits — достижение общего T_base. Так снижение критерия успеха видно
отдельно от расширения выборки. GUI-переключения в исходную SQLite не записываются.

Для фиксации k при построении БД можно передать --threshold-multiplier командам
build_analogs.py или russian_market.py; по умолчанию 1. Пересчитывать тики и
эмбеддинги ради просмотра/сравнения k не требуется. Применение выбранного по сентябрю
k к тому же сентябрю — исследование параметра; независимую проверку проводят позже.

Результат сравнения: [docs/threshold-tuning-results.md](docs/threshold-tuning-results.md).
